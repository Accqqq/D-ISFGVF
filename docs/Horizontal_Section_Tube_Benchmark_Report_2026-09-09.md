# 新水平截面 Tube 独立构建速度实测

日期：2026-09-09

## 1. 结论

只测当前 buildSectionTube，没有比较 SUPER，也没有优化或修改构建器。

本次固定输入中，直线+1,024个障碍盒的P50为2.366 ms；固定B-spline+256盒的P50为2.163 ms。障碍数增加后耗时上升：直线+4,096盒P50为9.511 ms，固定B-spline+4,096盒P50为26.227 ms，但后者只返回90%相位覆盖，不能算完整构建。

直线12,000盒和B-spline4,096盒均达到默认200,000次障碍检查预算，保持原配置返回PARTIAL。没有增大预算、缩短请求范围或删去失败样本来改善数字。

## 2. 测量方法

- CPU：Intel Core i5-12400，12逻辑CPU。
- benchmark进程单线程固定CPU 2；没有暂停其他进程、改系统频率或运行ROS仿真。
- governor仍为powersave，频率未锁定；机器有正常背景负载，故报告P95/P99/max而非只给最好值。
- Release：C++14、O3、DNDEBUG、ffp-contract=off，无sanitizer/fast-math/native特化。
- 当前section_tube.cpp、continuous_phase_path.cpp、UniformBspline_3d.cpp从源重新编译；没有使用原devel中的旧库。
- 每场景10次warmup、200次正式计时，共13场景、2,600条主测量。
- 主计时只包buildSectionTube调用，包含内部路径求值、界查询、seed/plane计算、几何与正则性检查、细分、PWL装配及内部缓存清理。
- 输入生成、路径构造、地图提取、profile移交/后续检查/析构、CSV和stdout在计时外。
- 另外每场景20次带callback计时的诊断，共260条，不混入主统计。
- P50/P95/P99使用nearest-rank，保留全部测量，不删除离群值。主会话从raw.csv独立重算13组统计，与harness输出全部一致。
- 所有重复构建的状态/节点/计数与各自基准结果一致；13组首个有效结果的计时外有限安全交叉验证均通过。有限检查不代替连续数学保证。

基准输入为合成完整已知局部环境，障碍采用互不重复的0.1m AABB。它不是飞行日志、实际局部点云或生产路径回放。B-spline使用固定控制点和当前工程的真实路径求值/界代码，不是用解析直线假扮B-spline。

完整输入和方法见 [测量规格](Horizontal_Section_Tube_Benchmark_Spec_2026-09-09.md)。

## 4. 覆盖、宽度与工作量

- 直线无障碍：20个cell、21个节点、全宽2m。
- 直线64/256/1,024/4,096盒：完整覆盖，全宽约1.600m，符合墙距1.2m减clearance0.4m的左右边界；不是靠缩成零宽取得速度。
- 直线12,000盒：200,000次障碍检查后截断，返回[0,1.6]，覆盖80%，全宽仍约1.600m。完整几何本身并非被证明阻塞，而是工作预算耗尽。
- arc各组完整覆盖，20个cell、21个节点、全宽2m。
- B-spline无障碍和256盒：均访问52个cell、最大细分深度1、42个节点，完整覆盖[4,7]。52×256=13,312次障碍检查。
- B-spline4,096盒：第49个访问cell期间达到200,000次障碍检查，返回[4,6.7]、38个节点，覆盖90%；没有测得该输入在原预算下的完整构建耗时。
- B-spline无障碍/256盒的最小全宽约1.006m，相位加权平均宽约1.725m。它没有保持名义2m全宽；本次没有测其理论最大宽度，因此速度结果不代表保守性已经解决。
- blocked_straight故意将障碍放到原路径上：只返回[0,0.599609375]，覆盖约29.98%。0.012ms是失败前缀处理耗时，不是绕障或完整构建成功。

## 5. 分项诊断

这是额外20次插入callback计时器的批次，单位ms、取均值。不能拿它逐项减去第3节不同批次的P50/P95。

| 场景 | 插桩总耗时 | point查询 | bounds查询 | 几何构建及其他 |
|---|---:|---:|---:|---:|
| straight_4096 | 17.086 | 0.001 | 0.001 | 17.084 |
| mapped_bspline_0 | 0.517 | 0.018 | 0.463 | 0.037 |
| mapped_bspline_256 | 2.171 | 0.020 | 0.460 | 1.691 |
| mapped_bspline_4096 | 26.430 | 0.030 | 0.460 | 25.940 |

剩余列包含障碍相关几何处理、平面/正则性/PWL、缓存和插桩自身等开销，不是直接测得的“单独障碍检查时间”。

固定B-spline空环境的bounds查询约0.463ms；4,096盒时仍约0.460ms，而剩余部分约25.940ms。结合障碍检查计数，当前大输入下主要增长来自随障碍量增长的几何处理，而不是路径查询本身。没有对内部每个函数作精确profile，故不进一步宣称某一个私有函数独占这些时间。

straight4,096盒主批次P50/P95差异较大，插桩批次也更慢。背景负载、缓存/分配器状态与未锁频均未隔离，不将两批差异归因于某个已证明的系统原因，也不删除高耗时样本。
